# 让 AI 在 AWS 上搭建 VPN 与订阅

把下面的完整 Prompt 交给具备终端、AWS 和 SSH 操作能力的 AI，让它完成节点搭建、可选的订阅服务、客户端配置和连接验证。你只需要提供需求、登录自己的 AWS 账号、确认费用，并在手机或电脑上验收。

## 使用前准备

- 一个有权限创建所需资源的 AWS 账号。登录和 MFA 在官方页面完成，不把密码、验证码或 Access Key 粘贴给 AI。
- 一台可以运行 AI 助手的电脑，以及在新节点建好前仍能访问 AI 和 AWS 的网络。普通网页聊天若没有执行工具，只能协助规划。
- 要使用的设备与客户端名称。已有节点或订阅时，提供资源名称、区域和私有配置的本机路径，让 AI 检查复用，不必重新搭建。

修改 Prompt 中的“我的需求”即可：可以从零完成搭建与订阅，也可以只建节点，或仅给已有节点配置订阅。不确定的项目保留默认值，让 AI 检查后提出方案。

订阅用于分发配置，实际代理流量仍由客户端直接连接 VPN 节点。下面的订阅方案面向 VLESS REALITY；WireGuard 按设备维护独立配置，不加入这份订阅。

## 完整搭建与订阅 Prompt

```text
请帮我在 AWS 上完成个人自用的 VPN/代理方案，按我选择的范围完成部署、
客户端配置、可选订阅和连接验证。请用中文与我沟通。

我的需求：
- 任务范围：从零搭建节点并配置订阅。
  也可改为“只搭建节点”或“仅给已有节点配置订阅”。
- 区域：东京（ap-northeast-1）。
- 节点数量：先建 1 个；仅配置订阅时不新增节点。
- 设备与客户端：iPhone / Shadowrocket；Windows / Clash Verge Rev。
- 已有实例或节点：无；已有则填写名称、区域及私有配置的本机路径。
- 已有订阅服务：无；已有则填写资源名称、区域及本机维护文件路径。
- 月预算：尚未确定，请查询当前费用并让我确认。
- 目标网站：github.com、www.cloudflare.com，以及我补充的网站。
- 路由规则：沿用现有规则；没有时先提出方案。
- 必须走代理的域名：无；有则补充具体域名。
- 协议：根据客户端与实际网络选择，先说明理由；已有节点保留原协议。
- 私有工作目录：请在本机选择专用目录，确保不在任何 Git 工作树中。

一、核实范围、环境和费用
检查本机工具、AWS 登录身份、区域和权限。优先使用现有临时登录态、
IAM Identity Center 或 CloudShell；需要我登录时给出明确入口，不创建根用户 Access Key。
核对已有资源归属、服务、端口和私有配置，保留现有客户端身份与无关服务。
复用订阅服务前核对执行角色和本地令牌；同名资源归属不明或本地令牌丢失时，
先报告，不覆盖资源或自动换证。
仅配置订阅时，只读取并验证已有节点，不重装服务或更换密钥。
需要新建节点时，查询当前 Lightsail 套餐和 Ubuntu LTS 镜像，选择内存够用、
支持公网 IPv4 并能绑定同区域静态 IPv4 的方案。
需要订阅时，可采用 AWS Lambda Function URL，查询当前部署要求和计费方式。
列出拟创建或复用的资源、月度基础费用、流量额度、超额收费及停止使用后的清理方式。
让我确认具体方案和费用后，连续完成授权范围内的工作，不重复询问环境中可查的信息。

二、搭建节点（仅在任务范围包含节点搭建时执行）
创建或复用已确认的实例，绑定静态 IPv4。先核对当前官方文档、软件版本、
服务器架构和端口占用，再安装受支持的版本。
按客户端兼容性选择一种主方案：Shadowrocket 和 Clash Verge Rev 可采用
VLESS + REALITY / TCP 443；需要官方 WireGuard 客户端时采用 WireGuard。
默认轻量部署并使用系统服务管理、开机启动，不安装 Docker 或管理面板。
检查 Lightsail 与系统防火墙，分别核对 IPv4、IPv6 和 TCP、UDP 规则；
只开放所需入口，SSH 使用密钥并限制合理来源，确认管理连接仍然可用。
VLESS + REALITY 要生成有效参数，实测 target、SNI、握手和客户端兼容性；
优先使用静态 IPv4 作为可验证的出口，每台设备使用可单独撤销的客户端身份。
WireGuard 要检查网段冲突，配置转发、NAT、DNS、路由及适合实际路径的 MTU，
每台设备使用独立密钥与隧道 IP。可测试 UDP 443 或 51820，不假设端口一定可用。
TCP 443 与 UDP 443 分别检查；已有 QUIC 等 UDP 服务时不要抢占 UDP 443。
如果只采用 WireGuard，说明本次 VLESS 订阅不适用，跳过第四部分，不额外安装其他协议。

三、生成客户端配置
以一份私有节点清单为唯一来源，派生所需客户端产物，保持 UUID、SNI、
REALITY 参数和节点名称一致。按设备或使用者的授权范围生成配置，
保留独立身份与单独撤销能力，不把不同设备的全部凭据混入一份共用配置或订阅。
Clash Verge Rev 交付包含节点、策略组、rules 和必要 DNS 设置的完整 YAML，
用兼容的 Mihomo 内核校验；必须代理的域名放在直连或兜底规则之前，
检查本地覆写是否影响结果。
Shadowrocket 交付可导入的节点配置；规则通过独立的配置或模块维护，
明确哪些请求代理、哪些直连，以及 IPv6 和 DNS 的处理边界。
官方 WireGuard 客户端交付各设备独立的配置文件。
需要扫码导入时生成对应二维码并反向解码，确认与原始配置完全一致；
交付参数不得保留示例占位符。

四、配置固定订阅地址（仅在任务范围包含订阅且节点为 VLESS REALITY 时执行）
先按第五部分从客户端侧验证每个节点，列出有效与失效节点；
不把只通过格式校验、未经连接验证的节点当作可用节点发布。
从第三部分的同一来源生成两类订阅：
Clash Verge Rev 使用完整 YAML，包含节点、策略组和规则；
Shadowrocket 使用客户端可识别的 Base64 VLESS URI 列表，只更新节点，
需要同步规则时另交付配置或模块，不声称节点订阅会同时更新规则。
按设备或使用者的授权范围提供固定 HTTPS 地址，两个客户端分别使用对应格式的 URL，
以高强度随机令牌保护下载。若使用公开访问的 Lambda Function URL，
按当前 AWS 要求配置调用权限，并在应用层校验令牌；
未知路径或无效令牌不返回节点内容，不记录完整请求路径、令牌或响应正文，
禁止缓存敏感订阅内容，设置最小执行权限、合理调用限制和日志保留时间。
普通节点增删与配置更新保持订阅 URL、令牌和未撤销的设备身份不变。
发布前校验全部产物；为 Shadowrocket 的原始 HTTPS 订阅 URL 生成二维码，
反向解码确认一致，标明这是订阅二维码，与单节点二维码区分。

五、用实际连接验收
检查服务状态、监听端口、错误日志、内存和磁盘余量。
从客户端侧显式连接每个节点，完成协议握手，验证出口 IP 与预期一致，
排除本机已有代理的干扰；不能用服务器直接访问网站代替客户端测试。
每个节点连续进行至少 10 次 HTTPS 请求，记录成功率、连接耗时和总耗时，
并测试 DNS 与目标网站。失败时依据日志、路由和抓包定位，不只凭超时判断端口被封锁。
在已授权范围内修复后重测；仅配置订阅时遇到节点故障，报告影响并先取得修复授权。
若配置了订阅，重新下载两种远端产物，核对格式、节点数量、参数和无效令牌拒绝行为。
指导我在 Clash Verge Rev 刷新订阅并核对节点、策略组与规则；
Shadowrocket 按“订阅”导入并核对节点，独立配置或模块的规则另行核对。
扫码无反应时，提供手动填写订阅 URL 的方法。
给出最少的操作步骤，让我在实际客户端、Wi-Fi 与蜂窝网络分别测试连接和出口。
HTTP 200 只证明订阅可下载；服务启动、端口可达、节点连通和真机可用分别记录。
没有执行工具或无法代替我完成的真机测试标明“待验证”或“待用户验收”，不记为通过。

六、保留可维护、可恢复的交付结果
修改前备份现有配置；更新订阅前备份远端实际部署版本及恢复所需配置，
失败时恢复并重新验证。替换资源、扩大费用或中断已有连接前先说明影响并取得确认。
保存私有节点来源、生成与部署脚本、配置备份，以及脱敏维护说明，
记录资源、版本、文件位置、新增节点或设备、撤销访问、恢复和释放收费资源的方法。
凭据、私钥、完整配置与 URL、部署包、二维码都留在私有目录：
目录权限 0700、敏感文件 0600，或当前系统的等效访问控制；不提交 Git、公开分享或打印日志。
更换订阅令牌需单独授权，采用可恢复的切换步骤，验证新 URL 可用、旧 URL 失效。
令牌只能控制后续下载，不能撤销已下载的节点凭据；泄露时还需撤销或更换相关节点身份。

完成后简洁交付：资源与费用摘要、按设备标注的私有配置和二维码位置、
订阅地址文件与导入步骤（若配置）、已验证结果、待我配合的事项和维护说明。
需要我登录、确认费用、授权权限或操作真机时，明确告诉我具体动作；
其余已授权工作继续完成。
```

具体命令由 AI 根据执行时的环境生成，脚本保存在本机。你不必逐段复制部署代码，但仍需确认费用、授权范围和实际设备上的使用结果。

## 怎样导入和验收

| 交付方式 | 应该看到什么 |
| --- | --- |
| 单节点配置或二维码 | 对应设备能导入并连接；这是固定配置，不会自动取得新增节点 |
| Clash Verge Rev 订阅 | 导入远程 YAML，刷新后能看到节点、策略组和规则，同时检查本地覆写 |
| Shadowrocket 订阅 | 按“Subscribe / 订阅”添加原始 HTTPS 地址或扫码；确认建立订阅记录，规则另行维护 |
| 实际访问 | 请求确实选择了该节点，出口符合预期，目标网站能连续访问；Wi-Fi 与蜂窝网络分别记录 |

浏览器打开订阅地址后显示文本、Base64 或下载 `.txt`，不一定是错误，最终以客户端能否正确读取为准。订阅地址和二维码包含访问凭据，应私密保存。

“服务已启动”“订阅可下载”和“手机实际能上网”是不同的验证结果。规则模式下，只有命中代理规则的请求才会经过节点，验收时先确认测试请求选择了正确节点。

## 后续怎么让 AI 继续维护

在原会话中说明目标即可，例如：“新增一台手机，使用独立凭据”“检查这个节点，蜂窝网络连续几次请求失败”“增加新加坡备用节点，先给出新增费用”。

更新订阅时可以说：“把这个私有配置路径中的新节点加入现有订阅，保持订阅地址不变，验证后告诉我如何刷新。”订阅只分发配置变化，节点故障和分流规则仍需分别排查。

新会话应提供之前交付的脱敏维护说明和私有文件路径。不要把完整订阅地址、密钥或二维码放入公共仓库。

## 供 AI 核对的官方资料

资源与权限参考 [AWS Lightsail 文档](https://docs.aws.amazon.com/lightsail/latest/userguide/getting-started-with-amazon-lightsail.html) 和 [Lambda Function URL 访问控制](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html)；协议配置参考 [Xray REALITY 文档](https://xtls.github.io/config/transports/reality.html) 和 [WireGuard 入门文档](https://www.wireguard.com/quickstart/)。Clash Verge Rev 的导入方式参考 [官方 URL Schemes 与订阅响应头说明](https://www.clashverge.dev/guide/url_schemes.html)。执行时核对当前版本、费用与客户端行为。
