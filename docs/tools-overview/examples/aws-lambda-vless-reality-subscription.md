# 让 AI 为 VPN 节点配置订阅

已有可用的 VLESS REALITY 节点后，可以让 AI 把它们整理成固定订阅地址。手机和电脑导入一次，新增节点或更新配置后刷新订阅即可。

还没有节点时，先使用 [让 AI 在 AWS 上搭建 VPN](./aws-lightsail-wireguard-vpn) 中的完整 Prompt。本页处理已有节点的配置分发，实际代理流量仍从客户端连接节点，订阅服务只在更新配置时使用。

## 使用前准备

提供已有节点配置的本机路径，以及要使用的客户端名称。优先让 AI 读取私有文件，不把 UUID、私钥或完整订阅链接粘贴进公开文档。

两种客户端需要的交付内容不同：

| 客户端 | 订阅内容 | 规则如何更新 |
| --- | --- | --- |
| Clash Verge Rev | 完整 YAML，包含节点、策略组和 rules | 可随订阅一起更新，还要检查本地覆写 |
| Shadowrocket | 多条 VLESS URI 编码成的 Base64 文本 | 这种订阅只更新节点，规则通过客户端配置或模块维护 |

WireGuard 继续按设备维护独立 Peer 和私钥，不加入下面这份 VLESS 订阅。

## 完整订阅 Prompt

```text
请把我已有的 VLESS REALITY 节点改成可持续更新的私有订阅，
完成生成、部署、验证和客户端导入交付。请用中文与我沟通。

我的需求：
- AWS 区域：东京（ap-northeast-1）。
- 已有节点配置路径：<填写本机私有文件或目录的路径>。
- 客户端：Shadowrocket、Clash Verge Rev。
- 已有订阅服务：<没有则填“无”，已有则填资源名称、区域与本机维护文件路径>。
- 路由规则：沿用现有规则；没有时先提出方案。
- 必须走代理的域名：<按需填写，没有则填“无”>。
- 月预算：先告知订阅服务的预计费用及计费方式，由我确认。
- 私有工作目录：选择本机专用目录，确保不在任何 Git 工作树中。

一、检查已有状态并确定范围
检查 AWS 登录身份和必要权限，读取我指定的节点配置，核对配置来源与服务端一致性。
先从客户端侧验证每个节点的握手、实际请求和出口，列出有效与失效节点；
不要把只通过格式校验的节点当成可用节点发布。
复用已有订阅服务前检查资源归属、执行角色和已有令牌文件。
若发现同名但归属不明的资源，或本地丢失已有订阅令牌，先报告，不覆盖或自动换证。
新建服务可采用 AWS Lambda Function URL。查询当前费用和部署要求，
列出具体资源、权限和费用让我确认；确认后连续完成部署与验证。
本次只管理订阅，保留节点服务、现有客户端身份和无关资源。

二、建立可重复更新的订阅
以一份私有节点清单为唯一来源，自动派生两个客户端的产物，
避免分别维护容易不一致的 UUID、SNI、REALITY 参数和节点名称。
按设备或使用者的授权范围生成各自订阅，保留已有的独立客户端身份和单独撤销能力，
不把不同设备的全部凭据混进一份共用订阅；同一设备的两个客户端使用对应的同一身份。
为 Clash Verge Rev 生成完整 YAML，补齐策略组、规则、必要的 DNS 配置和有效引用；
把必须代理的域名放在直连或兜底规则之前，并检查本地覆写是否影响结果。
为 Shadowrocket 生成它可以识别的 VLESS 节点订阅；
需要同步规则时单独交付匹配的配置或模块，明确两者的导入方式。
所有参数均按当前客户端版本验证，移除示例占位符，WireGuard 不进入这份订阅。

三、部署固定 HTTPS 入口
使用高强度随机令牌保护每个授权范围的订阅，两个客户端分别使用固定 URL。
若采用公开访问的 Lambda Function URL，按当前 AWS 要求配置调用权限，
并在应用层校验令牌；未知路径和无效令牌不返回任何节点内容。
不记录完整请求路径、令牌或响应正文，并禁止缓存敏感订阅内容。
按实际需要设置最小执行权限、合理的调用限制和日志保留时间。
节点新增和普通配置更新应保持 URL 与令牌不变。

四、验证并交付
先用与 Clash Verge Rev 兼容的 Mihomo 内核校验完整配置，再发布。
重新下载两个远端订阅，检查响应格式、节点数量、参数一致性和无效令牌拒绝行为。
为 Shadowrocket 的原始 HTTPS 订阅 URL 生成二维码，反向解码确认完全一致。
指导我按“订阅”导入；如果扫码无反应，提供手动填写 URL 的方法。
在 Clash Verge Rev 刷新并核对节点、策略组与规则；在 Shadowrocket 核对订阅节点，
有独立配置或模块时另行核对规则。两个客户端都要测试实际连接和出口。
HTTP 200 只代表订阅可下载，不能替代节点连通性或手机验收。
无法操作的设备或缺失的测试工具要明确记录，不把未执行的检查写成通过。

五、让更新和恢复有据可依
在私有目录保存节点来源、生成与部署脚本、配置备份和脱敏维护说明。
更新前备份远端实际部署版本及恢复所需的配置，失败时恢复并重新验证。
更换令牌需要单独授权，并设计可恢复的切换步骤；验证新 URL 可用且旧 URL 失效，
再交付新地址和二维码。订阅令牌只控制下载，不能撤销已下载的节点凭据。
怀疑凭据已经泄露时，说明还需要单独撤销或更换相关节点身份。
私钥、节点清单、完整 URL、订阅产物、部署包和二维码全部留在私有目录，
目录权限 0700、敏感文件 0600，或当前系统上的等效访问控制；不提交到 Git。

完成后按设备或使用者标注两个客户端的私有订阅地址文件、Shadowrocket 订阅二维码、
导入步骤、有效节点清单、验证结果和“新增节点后如何更新”的维护说明。
需要我登录、确认新增费用、授权权限或操作真机时，明确告诉我具体步骤，
其余已授权工作持续完成。
```

## 导入时看什么

Clash Verge Rev 使用远程订阅导入完整 YAML。Shadowrocket 使用“Subscribe / 订阅”添加原始 HTTPS 地址，或扫描订阅二维码。浏览器打开后显示文本、Base64 或下载 `.txt`，通常只是订阅响应的呈现方式，最终以客户端能否正确读取为准。

节点二维码导入一份固定配置；订阅二维码保存更新地址。验收时确认客户端建立了订阅记录，刷新后能取得最新节点。订阅地址包含访问凭据，应与配置文件一样私密保存。

## 后续只需描述要改什么

在原会话中告诉 AI：“把新节点加入现有订阅，保持订阅地址不变，验证后告诉我刷新结果。”同时提供新节点的私有配置路径。新会话则补充先前交付的脱敏维护说明和工作目录。

订阅更新负责把变化送到客户端，节点故障仍需要独立排查。规则模式下某个网站没有走代理，也应检查它实际命中的规则，而不是重复生成订阅。

## 供 AI 核对的官方资料

公开入口的权限行为参考 [AWS Lambda Function URL 访问控制](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html)。Clash Verge Rev 的导入方式与更新提示参考 [官方 URL Schemes 与订阅响应头说明](https://www.clashverge.dev/guide/url_schemes.html)。实现时应按实际客户端版本验证。
