# Agentic Coding：从对话协作到自主编码

## 背景

Vibe Coding 教会我们如何通过"目标 + 上下文 + 约束"的结构化对话，让 AI 高质量地完成编码任务。但随着 AI 工具的能力快速演进——Background Agent、多文件编排、终端访问、浏览器控制——一种新的协作形态正在浮现：**AI 不再只是"你问我答"的对话对象，而是能够自主规划并执行多步骤任务的行动者。**

这种形态在 2025–2026 年被行业广泛称为 **Agentic Coding**（自主编码）。

本文梳理 Agentic Coding 与 Vibe Coding 的关系，帮你判断什么时候该从对话模式升级到自主模式，以及升级后需要注意哪些新的风险。

---

## Vibe Coding 与 Agentic Coding 的关系

Agentic Coding 不是对 Vibe Coding 的否定，而是它在更高自治级别上的自然延伸。

| 维度 | Vibe Coding | Agentic Coding |
|------|------------|----------------|
| 核心模式 | 人主导对话，AI 按轮次响应 | 人给目标和边界，AI 自主规划执行 |
| 输入粒度 | 每轮给出具体指令或约束 | 一次性给出任务目标、约束和验收标准 |
| 典型交互 | 4 轮推进：目标→约束→方案→验证 | 1 轮启动 + 多次异步检查 |
| AI 能力要求 | 理解上下文、生成代码 | 规划步骤、调用工具、观察结果、自我修正 |
| 人类角色 | 每轮引导方向、审核输出 | 定义目标、设计约束、验收结果 |
| 适用场景 | 功能实现、bug 修复、探索性编码 | 跨文件重构、端到端功能交付、自动化工作流 |

可以用一个渐进谱系来理解：

```
补全 → 对话 → Vibe Coding → Agentic Coding
                  ↑              ↑
              人逐步引导      人定义目标，AI 自主执行
```

Vibe Coding 中你学到的所有原则——目标清晰、边界明确、验证先行——在 Agentic Coding 中不但没有失效，反而**更加重要**。因为 AI 的自主性越高，前置约束的质量就越决定最终产出。

---

## Agentic Coding 的核心特征

### AI 拥有自主行动能力

在对话模式下，AI 的能力边界是"接收文本→返回文本"。而在 Agentic 模式下，AI 可以：

- **读写文件**：浏览代码库，定位上下文，直接修改文件
- **执行命令**：运行测试、构建项目、安装依赖
- **使用浏览器**：打开页面、检查渲染结果、截图对比
- **调用外部工具**：通过 MCP 访问数据库 schema、查阅 API 文档、搜索代码库
- **自我验证**：运行代码后检查输出、发现错误后自主修复

### 工作流从"多轮对话"变为"任务委派"

Vibe Coding 的典型流程是"你一轮、我一轮"的乒乓式协作。Agentic Coding 的流程更像委派一个任务给团队成员：

```
你：定义任务 + 约束 + 验收标准
   ↓
AI：规划步骤 → 逐步执行 → 遇到问题自主调整 → 输出结果
   ↓
你：审核结果 + 关键点 review
```

### 一个对比场景

**同一个任务："给现有的 REST API 补充分页功能"**

Vibe Coding 的做法：

```
第 1 轮：描述需求——给列表接口加分页，用 offset + limit
第 2 轮：补约束——保持返回格式兼容，默认 limit=20，最大 100
第 3 轮：要方案——先列出要改的文件和改法
第 4 轮：实现并验证——运行测试，确认回归
```

Agentic Coding 的做法：

```
一次性任务描述：
- 目标：给所有列表接口加分页
- 约束：offset + limit 参数，默认 20，最大 100，保持返回格式兼容
- 验收：现有测试通过，新增分页测试覆盖边界情况
- 不能改：认证和权限逻辑

AI 自主完成：
1. 扫描代码库，找到所有列表接口
2. 分析现有返回格式
3. 设计通用分页方案
4. 逐个接口实现修改
5. 补充测试
6. 运行全部测试，修复失败项
7. 输出改动摘要
```

两种方式都能完成任务。区别在于 Vibe Coding 是你在过程中持续参与，而 Agentic Coding 是你在前后两端参与——**前端定义得越精确，后端验收就越轻松**。

## 什么时候该用 Agentic 模式

### 适合用 Agentic 模式的场景

- **跨多文件的结构性改动**：重命名、迁移、统一接口风格
- **有明确验收标准的端到端任务**：测试可运行、构建可通过
- **重复性高但需要上下文理解的批量操作**：每个文件的改法不完全一样，不能用简单脚本
- **探索性原型**：快速验证一个技术方案是否可行

### 不适合用 Agentic 模式的场景

- **安全和权限相关逻辑**：需要人逐行审核
- **业务规则复杂且缺少测试保护的代码**：AI 自主修改的风险太高
- **需要频繁与人讨论方向的探索**：Vibe Coding 的交互式推进更合适
- **团队没有基本的 Harness**：没有 Rules、没有测试、没有 CI，AI 自主性越高出错越隐蔽

### 一个决策辅助

```
任务可以用测试自动验证？
  ├─ 是 → 任务涉及多文件或多步骤？
  │        ├─ 是 → 考虑 Agentic 模式
  │        └─ 否 → Vibe Coding 就够了
  └─ 否 → 任务涉及安全/权限/核心业务逻辑？
           ├─ 是 → 精确控制模式
           └─ 否 → Vibe Coding + 人工验收
```

## Agentic Coding 引入的新风险

Agentic Coding 带来效率提升的同时，也放大了一些在对话模式下不太显著的风险。

### 幻觉包攻击（Slopsquatting）

AI 可能在代码中引入实际不存在的依赖包。攻击者提前注册这些"高频幻觉包名"，开发者安装后即被植入恶意代码。研究显示约 20% 的 AI 代码样本引用了不存在的包。

**应对方式**：在 Rules 中加入反幻觉规则——要求 Agent 在 import 前验证包是否存在（`npm list`、`pip show`）。

### 隐蔽的回归

AI 在自主修改多个文件时，可能在不经意间改变了已有行为。在对话模式下，你每一轮都在看 diff；在 Agentic 模式下，改动可能分散在十几个文件中。

**应对方式**：让 Agentic 任务必须以"全部测试通过"作为完成条件，并配合 pre-commit Hook 做关键路径检查。

### 上下文丢失与漂移

长时运行的 Agent 可能在执行过程中逐渐偏离最初目标，特别是当上下文窗口不足以容纳所有相关信息时。

**应对方式**：为复杂任务设置检查点（checkpoint），要求 Agent 在关键节点暂停并汇报进展，而不是一路执行到底。

### 权限过大

Agentic 模式下 AI 拥有文件读写、命令执行等权限。如果没有合理的权限边界，Agent 可能删除配置文件、修改不该动的模块、执行危险命令。

**应对方式**：遵循最小权限原则。优先使用只读工具，写操作限制在目标目录内，危险命令（如 `rm -rf`、数据库迁移）必须经人确认。

## 实践要点

### 前置约束比过程干预更有效

对话模式下你可以每一轮纠偏；Agentic 模式下 AI 在中途执行时你通常不在线。这意味着：

- **Rules 必须到位**：CLAUDE.md 中的架构约定、编码规范、禁止行为，是 Agent 自主工作的底线
- **测试必须存在**：没有测试的代码让 Agent 修改，等于在没有护栏的路上开快车
- **验收标准必须明确**：不能是"做好一点"，而是"测试通过 + 格式检查通过 + 不改动 X 目录"

### 从小任务开始委派

不要一上来就把整个功能模块交给 Agent 自主完成。建议的路径：

1. 先用 Agentic 模式完成单文件的测试补充
2. 再试跨两三个文件的小重构
3. 确认 Agent 能稳定遵守约束后，逐步扩大任务范围

### 审核改动而不是审核过程

在 Vibe Coding 中你审核每一轮的输出。在 Agentic Coding 中你审核最终结果。这要求你：

- 优先看高风险文件的 diff（安全、权限、核心业务逻辑）
- 确认测试真的覆盖了关键路径，而不只是 happy path
- 检查 Agent 是否引入了不在预期内的新依赖

## 常见误区

| 误区 | 更稳妥的判断 |
|------|-------------|
| "Agentic Coding 就是让 AI 全自动写代码" | 自主不等于无监督。人的职责从"逐行写"变为"定义目标 + 设计约束 + 验收结果" |
| "用了 Agentic 模式就不需要 Vibe Coding 了" | 两者是谱系而非替代。很多任务在 Vibe 模式下更高效，强行用 Agentic 只会增加复杂度 |
| "AI 能自主修复所有错误" | Agent 能修复它能检测到的错误。对于逻辑错误、业务规则违反、安全漏洞，仍需人来判断 |
| "多给权限才能让 Agent 发挥全部能力" | 权限越大，失控时的破坏越大。最小权限 + 逐步放开是更安全的路径 |

---

## 小结

Agentic Coding 是 Vibe Coding 的自然进化——从"人引导每一步"到"人定义目标，AI 自主执行"。

但这种进化不是免费的。它要求：

- **更高质量的前置约束**：Rules、测试、验收标准必须在任务开始前就位
- **更成熟的 Harness 体系**：Context、Constraints、GC 三层配合，才能让 Agent 自主性与可靠性并存
- **更精准的风险判断**：知道什么任务适合委派，什么任务必须保持人在回路

如果你在 Vibe Coding 阶段的基础打得扎实——目标清晰、约束完整、验证到位——那么向 Agentic Coding 的过渡会非常自然。如果基础不牢，Agentic 模式只会更快地放大问题。

回到 Vibe Coding 的核心原则：**质量差异不出现在第一轮，而出现在约束和验证的质量上。** 在 Agentic Coding 时代，这句话比以往更加成立。
