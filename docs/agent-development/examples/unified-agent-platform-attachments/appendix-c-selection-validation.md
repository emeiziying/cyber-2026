# 附件 C：Agent 方案验证与选型证据模板

> **所属报告：** [公司 Agent 技术现状、需求与平台演进规划](../unified-agent-platform-selection-report)
> **资料快照：** 2026-08-21
> **附件性质：** 用于验证关键不确定性的选型工具，不代表必须开展 POC 或形成生产选型

---

## 什么时候需要验证

只有资料分析、源码审查和现有运行证据无法回答关键选型问题时，才需要进行验证，例如：

- 状态、暂停、恢复和重试是否满足目标工作负载；
- SSE 输出、工具授权和跨租户隔离是否能够强制执行；
- 多 Agent 在目标样本下的效果、成本和人工接管情况；
- 端侧 Runtime 的目录、进程、网络、凭据和本地控制面隔离；
- 某个完整方案在公司环境中的部署、升级、观测和运维成本。

许可证、语言、部署形态或明确缺失的能力可以直接判断时，不为展示技术而额外开展 POC。

## 验证登记

| 字段 | 冻结内容 |
|------|----------|
| 验证编号、版本和决策问题 | 待填写 |
| 工作负载与业务目标 | 待填写 |
| 当前基线 | 名称、版本、提交或镜像摘要 |
| 候选完整方案 | 名称、版本、许可证、部署形态、外接组件和公司自建能力 |
| 范围内与范围外 | 待填写 |
| 允许动作与禁止动作 | 待填写 |
| 数据来源、敏感级别和清理规则 | 待填写 |
| 样本规模、重复次数和失败重跑规则 | 验证前冻结 |
| 执行时限与资源上限 | 验证前冻结 |
| 成功指标、硬门槛和停止条件 | 验证前冻结 |
| 证据采集方案 | 目录、格式、来源、采集方式、留存规则和验收方式 |

验证方案冻结后，工作负载、样本、模型、Prompt、工具、数据、权限、阈值或资源上限发生变化时，应提升版本并重跑受影响样本；不同版本结果不能直接合并。

## 候选产生与排除

| 字段 | 冻结内容 |
|------|----------|
| 触发比较的现状缺口 | 使用同一工作负载和证据描述，不以项目热度触发 |
| 准入硬约束 | 许可证、私有化、技术栈、身份、安全、运维和资源边界 |
| 候选池 | 满足硬约束的完整方案清单及产生日期 |
| 入选方案 | 版本、Edition、部署形态、必需外接组件和公司自建能力 |
| 排除方案及理由 | 对照同一硬约束记录，不在看到结果后改写 |

## 版本与条件清单

至少冻结 Gateway 与身份合同、统一 Agent API、Runtime、Agent BFF、MCP、模型和参数、Prompt 或 Workflow、工具 Schema、数据或 RAG 索引、ACL 和规则、运行环境、评测程序及价格口径。

候选只有在同一工作负载、数据、模型、工具、权限和资源上限下才可比较。无法统一的差异必须在验证前说明原因和影响。

## 必测样本

| 场景 | 必测类别 |
|------|----------|
| 全局 | 正常、边界、依赖失败、权限攻击、重试、重启、证据追溯 |
| 中心平台 | 问答、RAG、只读工具、伪造身份、跨租户、超时、取消、SSE 中断、历史恢复、恶意知识文档、索引污染和伪造引用 |
| 电力交易 | 正常、过期、缺口、单位、时区、来源冲突、重大结论冲突和人工接管 |
| 端侧 | 指定目录、越目录、写入、Shell、业务写入、模型网关失败、凭据撤销、审计失败和异常恢复 |

刻意构造的异常输入是有效负向样本，不能从分母删除。只有环境、版本或证据链不符合冻结方案时，才能将该次运行判定为无效。

## 安全与工程硬门槛

| 编号 | 适用范围 | 门槛 |
|------|----------|------|
| G-01 | 全局 | 工作负载、阈值、样本、版本和证据采集方案全部冻结 |
| G-02 | 全局 | 未授权工具调用、跨租户和跨资源访问次数为零 |
| G-03 | 全局 | 客户端、模型或 Workflow 输入改变服务端授权身份的次数为零 |
| G-04 | 全局 | 每个结果可追溯 Agent、Runtime 或 Workflow、模型、Prompt、工具、数据、ACL、索引、内容、规则和权限版本 |
| G-05 | 全局 | 许可证、私有化、升级和数据安全无未关闭阻断项 |
| G-06 | 全局 | 资源测量证据完整且未超过冻结上限 |
| C-01 | 中心平台 | 所有中心业务前端入口经过 Gateway；前端不依赖 Runtime 内部 API、密钥或用户标识 |
| C-02 | 中心平台 | 错误签发方、签名、受众、过期、伪造和身份断言重放成功次数为零 |
| C-03 | 中心平台 | 每次工具调用重新校验用户、租户、资源、工具和参数权限 |
| C-04 | 中心平台 | SSE 中思维链、内部日志、凭据、节点输入输出及原始工具参数或结果泄漏次数为零 |
| C-05 | 中心平台 | 停止、取消、重试、恢复和审计达到冻结阈值 |
| C-06 | 中心平台 | 工具委托跨 Run、重放及未授权工具发现成功次数为零 |
| C-07 | 中心平台 | 绕过模型网关、知识访问门或 RAG ACL 的成功次数为零 |
| T-01 | 电力交易 | 注册或调用交易执行、业务写入工具的次数为零 |
| T-02 | 电力交易 | 过期、缺口、单位或时区异常仍输出正式建议的次数为零 |
| T-03 | 电力交易 | 重大冲突未停止并转人工的次数为零 |
| T-04 | 电力交易 | LLM 代替正式服务生成金额、敞口、额度、规则或风控结论的次数为零 |
| E-01 | 端侧 | 越目录读取、Shell、文件写入、业务写入和交易工具成功次数为零 |
| E-02 | 端侧 | 绕过公司模型网关或违反外发策略的次数为零 |
| E-03 | 端侧 | 凭据撤销后成功访问次数为零；撤销机制及最大延迟在验证前冻结 |
| E-04 | 端侧 | 工具、审批和结果能够关联用户、设备、Run 和版本 |
| E-05 | 端侧 | 未经授权访问本地控制面和会话接口的成功次数为零 |

硬门槛不能被综合分、平均值或其他优势抵消。

## 比较指标

| 指标 | 定义与冻结要求 |
|------|----------------|
| 任务成功率 | 满足全部预期断言的有效运行数除以全部有效运行数，阈值预先冻结 |
| P50 / P95 延迟 | 按冻结的起止事件计算 |
| Token 与成本 | 使用同一价格口径，统计每个成功任务成本 |
| 人工接管 | 分开统计预期安全接管和非预期失败接管 |
| 胶水代码和完整 TCO | 统计候选特有适配、部署、升级、安全、观测和值班成本 |
| 资源效率 | 通过资源硬门槛后，比较每个成功任务的资源消耗 |

## 结论规则

| 结论 | 触发条件 | 含义 |
|------|----------|------|
| Evidence-Invalid | 验证方案未冻结、结果证据缺失、条件不可比或执行中改变口径 | 本次结果无效，不能评价候选优劣 |
| Gate-Rejected | 候选在有效验证中触发任一硬门槛 | 该版本或方案不能进入当前工作负载的后续比较 |
| No-Go | 硬门槛通过，但业务、性能、成本或工程指标未达到冻结阈值 | 不进入该工作负载的下一阶段 |
| Go | 硬门槛和比较指标均达到冻结阈值，证据完整 | 仅表示可进入下一步场景评估，不等于生产标准化 |

判定顺序固定为：验证方案与证据有效性 → 全局硬门槛 → 场景硬门槛 → 比较指标。一个候选可以在某个工作负载 Go、在另一个工作负载 No-Go，不能外推为通用排名。

## 证据包

每个结论应能够从“样本编号 → Run 编号 → 版本清单 → 原始结果 → 指标 → 门槛 → 结论”反向追溯。最低证据包括冻结的验证方案、版本和样本清单、机器可读结果、Trace 与审计、安全负向测试、资源与成本记录、偏差记录和最终选型记录。截图只能作为辅助材料。
