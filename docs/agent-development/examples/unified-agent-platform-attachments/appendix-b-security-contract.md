## 逐跳信任矩阵

共同规则：每个接收方只信任本跳已验证的服务身份和服务端派生上下文。客户端字段、模型输出、Runtime 内部用户标识、工具发现结果和 RAG 查询参数均不是授权依据。

| 跃点 | 仅可信依据 | 接收方强制责任 | 通过标准 |
|------|------------|----------------|----------|
| 客户端 → Gateway | Gateway 验证后的业务 Token 或会话 | 校验签名、受众和时效；删除外部身份 Header；派生用户、租户和应用 | 伪造 Header、过期 Token、错误受众全部拒绝并留痕 |
| Gateway → Agent API | 受众绑定、短时、防重放的签名身份断言，Gateway 服务身份及受保护链路 | 校验签发方、签名、受众、时效、Gateway 服务身份和 `jti/nonce`；绑定 Agent、会话、租户和业务资源；合同未落地前继续在线查询身份权威源 | 错误签发方、签名、受众、过期、伪造和重放断言全部拒绝；客户端不能指定用户或会话归属 |
| Agent API → Runtime | Agent API 服务身份、Agent 配置和本 Run 授权快照 | 固定 Runtime、模型、知识和工具范围 | Prompt、Workflow 输入和模型输出不能扩大权限 |
| Runtime → Agent API → 客户端 | Runtime 输出一律视为不可信 | 事件和字段白名单、Schema 校验、脱敏 | 思维链、内部日志、凭据和未裁剪工具数据不可见 |
| Runtime / 端侧 → 模型网关 | 受控服务或设备身份及 Run 上下文 | 模型白名单、数据分级、限额和审计 | 绕过模型网关的直连调用失败 |
| Runtime / 端侧 → 知识访问门 | 服务端绑定的用户、租户、资源和 ACL 快照 | 覆盖或拒绝模型提交的数据集与过滤条件 | 跨租户、ACL 缺失、版本不可用时不返回内容 |
| Runtime → 工具接入层 | 服务身份和绑定用户、租户、资源、Run 的短期委托 | MCP 工具发现与每次调用分别授权；受控业务 API 按同一规则校验白名单、参数和防重放；禁止直连原始后端 | 未授权、篡改、过期、跨 Run 和重放调用全部拒绝 |
| 工具接入层 → 业务后端 | 已验证服务身份和可信业务上下文 | 重新执行对象级权限、正式计算、规则、风险和幂等校验 | 模型或工具参数篡改不能绕过最终授权；只读 POC 不暴露写工具；服务凭据泄露作为独立阻断事件处置 |
| 端侧 → 中心平台 | 受管设备、用户、获批版本和短期凭证 | 校验设备状态、策略、目录范围和冻结的撤销机制 | 用户或设备撤销后，在安全责任人预先冻结的最大延迟内拒绝访问 |

## 模型与 RAG 强制路径

~~~text
中心 Runtime / 端侧候选 → 公司模型网关 → 获批模型
中心 Runtime / 端侧候选 → Agent API 知识访问门 → 获授权索引与内容源
~~~

强制路径必须由网络出口和凭据分配共同保证，不能只依赖 Prompt。Runtime、插件和端侧设备不得持有模型、向量库或内容源的长期直连凭据。每个 Run 必须关联模型、Prompt、Agent、ACL、索引和内容版本。

## 四类审计

| 审计类型 | 责任方 | 最小记录 |
|----------|--------|----------|
| 入口与资源授权 | Gateway、Agent API | 用户、租户、应用或设备、Agent、会话、资源、允许或拒绝、原因码、策略版本 |
| Run、模型与 RAG | Agent API、模型网关、知识访问门 | Run、Agent、Prompt、Runtime、模型、耗时、用量、检索范围、ACL、索引及引用版本 |
| 工具接入（MCP / 受控业务 API） | 工具接入层 | 工具或接口版本、委托、授权结论、参数和结果摘要、目标资源、重试、错误及下游状态 |
| 业务决策与执行 | 业务后端 | 正式计算和规则版本、风险、建议摘要、确认、有效期、幂等、执行、补偿和对账 |

四类记录以 traceId 和 runId 关联，并采用统一时间源、访问控制、完整性保护以及冻结的留存、删除和导出规则；身份、权限、模型、知识、工具和审计配置变更也须留痕。聊天历史、实时 SSE、平台 Trace 与业务审计是不同证据面；普通日志和聊天历史不得保存 Token、密钥、原始敏感行、完整工具结果或内部 URL。确需留存的原始敏感证据只能进入加密、限权的独立证据库。
