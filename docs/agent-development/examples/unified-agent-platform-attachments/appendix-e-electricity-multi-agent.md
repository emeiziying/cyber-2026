## 建议流程

~~~text
可信业务上下文
      │
确定性 Run Coordinator
      ├── 政策 / 规则 Agent（只读）
      ├── 市场数据 Agent（只读）
      └── 预测 / 策略 Agent（只读）
                │
        Schema / Evidence Normalizer
                │
       正式计算与确定性聚合服务
                │
          Risk Gateway 硬门禁
                │
        解释 Agent 生成可读说明
                │
      人工确认 / 业务系统重新授权执行
~~~

## 确定性与执行边界

- 专业 Agent 只做只读检索、分析和候选结论，输出来源、数据版本、时间窗、单位、假设、区间和置信度。
- Coordinator 固定参与 Agent、版本、依赖、超时、重试和状态迁移；模型不得增加 Agent、工具或执行步骤。
- Schema、新鲜度、单位、时区、金额、敞口、收益、额度、规则和风险由确定性代码或正式业务服务处理。
- 缺字段、证据不足、数据过期或重大冲突必须停止并转人工，不以多数投票消解。
- 解释 Agent 只能表述已冻结结果，不能修改正式数值、风险结论或执行资格。
- 人工确认绑定不可变建议摘要、用户、租户、版本和有效期；业务后端在执行前重新授权并校验最新数据与规则。

Coordinator 固定参与 Agent、工具和允许的状态迁移，但 LLM 产生的候选证据仍可能变化。确定性保证从冻结且校验通过的 EvidenceSnapshot 开始：相同快照和规则版本必须得到相同的正式计算与门禁结果；证据差异、缺失或冲突只能触发停止或人工接管，不能改变执行资格。
